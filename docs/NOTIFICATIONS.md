# Уведомления Telegram

## Расписание

| Тип | Условие | Когда | Класс |
| --- | --- | --- | --- |
| unclaimed_1/3/7 | без реферала, стартового бонуса и оплат | 1/3/7 суток от первого входа | предложение |
| help_20m | доступ выдан, инструкция не открыта, подключения нет | 20 минут | помощь по доступу |
| help_24h | доступ активен, подключение не подтверждено | 24 часа от выдачи | помощь по доступу |
| trial_d1 | пробный доступ, подключался, оплат не было | последние 24 часа | предложение |
| trial_help | те же последние сутки, но не подключался | вместо trial_d1 | помощь по доступу |
| d3/d1 | обычная подписка, без автопродления | 3/1 суток до конца | сервисное |
| expired | срок действительно закончился | день окончания | сервисное |
| expired_d3/7/30 | не продлил после окончания | 3/7/30 суток | предложение |
| payment_5m/24h | конкретный текущий счёт подтверждён как pending/canceled и paid=false | 5 минут / 24 часа | сервисное |
| autopay_failed | подтверждённая отмена автоплатежа, автопродление отключено | после проверки, с повторами доставки | сервисное |
| incident/recovered | явное подтверждение администратором | после команды | сервисное |

Старые отдельные циклы окончания, onboarding и trial_24h больше не запускаются.
Сохранённые старые отметки d1/d3/expired и отправки помощи через 20 минут
учитываются: повторной отправки при обновлении кода нет.

Короткие таймеры обрабатываются каждую минуту, основные цепочки каждые 15 минут.
Это время наступления права на отправку, а не гарантия доставки до секунды:
проверки панелей и Telegram могут задержать сообщение. Пропущенные исторические
ступени не догоняются пачкой: каждая дневная ступень имеет окно 24 часа.

## Проверки и ограничения

- Бонус, реферал и оплаты читаются заново из хранилища перед отправкой.
- Срок и активность читаются из основной панели без создания или продления
  клиента. Ошибки источника не считаются окончанием подписки.
- Подключение подтверждается трафиком больше 512 КиБ на основной или merged-ноде.
  Открытие инструкции не считается подключением. Если трафик нельзя достоверно
  проверить, сообщение о неподключении не отправляется.
- Только разрешённые для пользователя маршруты участвуют в проверке; неизвестный
  результат недоступной ноды не превращается в «пользователь не подключался».
- Предложения: максимум одно за скользящие 24 часа и три за скользящие 7 суток.
  Помощь после выдачи доступа, сообщения об оплате, сроке доступа и аварии
  сервисные и квоту не расходуют. Платёжные напоминания дополнительно ограничены
  одним в час независимо от числа созданных счетов.
- «не присылать предложения» сохраняется после перезапуска; сервисные сообщения
  остаются. Это ограничение автоматических цепочек, не произвольных ручных /notify.
- Во время подтверждённой аварии предложения, обычные напоминания об оплате и
  подключении приостанавливаются. Аварийные сообщения и сообщения об автосписании
  не скрываются.
- При включённом автопродлении ручные предложения продления подавлены. Если
  результат автосписания неизвестен, повторная оплата не предлагается до проверки.

## Счета

При создании сохраняются payment_id, план, время и ссылка. Напоминание проверяет
именно этот ID через API ЮKassa, владельца счёта, paid, status и применённую оплату.
Старый успешный платёж не отменяет новый неоплаченный счёт. Новый счёт заменяет
предыдущий в напоминаниях. awaiting capture / неизвестный статус / ошибка API не
считаются неоплатой. «я оплатил» проверяет текущий счёт, не историю платежей.

Для pending повторно открывается тот же счёт. Для canceled открывается выбор
способа оплаты с актуальной ценой: просроченную ссылку не выдаём за рабочую.
Записи счёта сохраняются также для покупки трафика, но новые рекламные цепочки
докупки трафика не добавляются.

Неопределённый результат автосписания сохраняется отдельно. Когда известен ID,
статус перепроверяется; при подтверждённой отмене ставится уведомление об ошибке.
При потерянном ответе без ID администратор сначала проверяет ЮKassa, затем:

```text
/notification_payment_checked <telegram_id> confirm
```

Команда только снимает паузу предложений/автопроверки. Она не начисляет дни,
не создаёт платёж и не включает отключённое автопродление.

## Аварии

```text
/incident open confirm
/incident resolved confirm
```

Только для существующих администраторов. Команды подтверждают известную общую
аварию/восстановление; один неудачный ping не включает массовую рассылку.
Об аварии уведомляются пользователи с выданным бонусом, оплатой или записью
доступа. Восстановление отправляется только тем, кому Telegram подтвердил
доставку сообщения именно об этой аварии. Повтор команды не создаёт дубль.

## Доставка и наблюдаемость

Состояние: `database/notifications.json`, права 0600, атомарная замена после fsync.
Файл содержит чувствительные ссылки счетов, исключён из Git. Не удалять его
при выкладке: в нём отказы от предложений, лимиты, счета и история доставки.
Рассчитано на один экземпляр бота: второй процесс с тем же файлом запускать нельзя.
Для нескольких реплик потребуется хранилище с транзакционными блокировками.

Перед Telegram записывается резервирование. Только успешный ответ с message_id
становится `sent` и вызывает лог «доставлено». Отклонение Telegram записывается
как `failed`, блокировка как `blocked`. Сетевой обрыв с неизвестным результатом
остаётся `unknown` (при падении процесса — `sending`): не отмечается доставкой и
автоматически не повторяется, чтобы не посылать дубли. Такие попытки резервируют
рекламную квоту до её истечения. Это не обещание exactly-once у внешнего API.

Логи используют существующую Telegram-беседу и `sendUserNotificationAdminLog`:
тип, ссылка/ID пользователя, дата, время; ошибки — отдельный тип, не успешная
доставка. Нажатия callback-кнопок сохраняются и логируются с типом сообщения.
Прямые URL-кнопки Telegram не сообщают боту о кликах: их переходы не учитываются
как достоверные события. Доставка означает приём Telegram, не прочтение человеком.

Подключения отслеживаются по трафику, оплаты по applied_payments; это наблюдения
после сообщений, не доказательство причинной связи с рекламой. Блокировка и
разблокировка также отслеживаются через my_chat_member.

## Проверки

```text
go test ./...
go test . -run TestNotice -count=1
go test -race . -run TestNotice -count=1
go vet ./...
```

Проверяются сроки, остановки, квоты, отдельные счета, числовой Telegram ID из JSON,
перезапуск, отказы доставки, неизвестная доставка, отказ от предложений, авария,
конкурентные отправки и отсутствие глобальной блокировки на сетевой проверке.
Race-тест требует CGO и C-компилятор. Проверки не посылают реальные сообщения.

Источники API:
- https://yookassa.ru/developers/payment-acceptance/getting-started/payment-process
- https://core.telegram.org/bots/api#inlinekeyboardbutton
